How it works

Evaluating from logs

A ranking system already shows lists and records clicks. If it shows lists with some randomness and writes down how likely each list was, those old logs can answer a new question: how many clicks would a different policy have earned?

Propensities

The propensity is the probability the old policy gave to the exact list it showed. When a new policy would show a list more often than the old one did, the clicks on that list count for more. The ratio of the two probabilities is the importance weight.

Why naive comparison misleads

Averaging clicks over the logged lists a new policy agrees with sounds fair, but the old policy chose those lists for a reason. It showed its favourite lists most often and in the contexts it liked best, so the matching rows are not a fair sample. Weighting by propensities undoes that choice.

The estimators

Inverse propensity (IPS)
Reweights every logged query by its importance weight. Unbiased, but noisy when weights are large.
Self-normalised IPS
Divides by the total weight instead of the row count. A little bias, much less noise.
Clipped IPS
Caps each weight at the clip level. Lower noise, but it pulls the estimate down.
Reward model
Learns a click model from the log and asks it about the new policy. Steady, but only as good as the model.
Doubly robust
Starts from the reward model and corrects it with weighted errors. Holds up if either part is right.

The check

The simulator knows every true click probability, so it can run the online test that real teams cannot run for free. The red line is that answer.

Column format

One row per query. Positions count from 1 at the top of the list. Lists may hold 2 to 6 items.

ColumnMeaning
query_idAny identifier
ctx_1 to ctx_3Query context features
item_KItem shown at position K
click_K1 if it was clicked, else 0
item_K_popPopularity feature of that item
item_K_f1 to item_K_f3Other item features
propensityProbability the logging policy gave the whole list it showed
target_propensityOptional. Probability your own policy gives that list
